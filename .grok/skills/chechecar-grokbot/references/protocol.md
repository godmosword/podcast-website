# GrokBot 場內協議

## Plan 三審（可連續、須分節輸出）

每審獨立標題，禁止把三審寫成一段綜合感想。

1. **工程車** — 可行性、漏檔、驗證命令；反駁 Task DAG ≥3 點
2. **找碉車** — 失敗模式、付費越權、素材外流、兒童安全
3. **黏土車** — DESIGN.md、主路徑、觸控、動畫、資訊層級

工程審必須有實質內容才可標 Approved。找碉／黏土缺席時仍列出該列。

## Action

- 不同檔可並列描述；禁止敘述上「同時改同一檔」
- 先 scout（路徑不明）再 builder；實作 prompt 填 Handoff 全欄
- Verify 對 Domain 矩陣逐項：已跑／須本機跑／跳過理由
- UI 風險屬性或 StoryPlayer／PlayButton／StoryCard／Chip／GamePageShell／LandingSegment／SiteNavBar → 黏土車不可省略
