## PR-J1 下一步：一次只亮一個

1. **新增 `lib/games/orange-express/next-action.ts`**（純函式，先寫測試）
   - `nextAction(state, ctx: { mission: boolean; releaseHint: boolean; coachOn: boolean; beat: CoachBeat }): NextAction | null`
   - `NextAction = { control: "power" | "brake" | "horn" | "door" | "point"; notch: number | null; dir: "up" | "down" | null; reason }`；`notch: null` 表示整根桿。`dir` 從目標格與目前格的位置算（兩根桿都是格子越大越在上面，Cab:135），不照桿子種類寫死。
   - **只在 View 算一次**：View 已有的 `coachBeat` 結果、`mission === "shown"`、已經 AND 過的 `releaseHint`（不用 `releaseReady`，它晚一次 commit）放進 ctx；結果傳給 Cab、前窗，`liveText` 也改看它。
   - 優先序（由上往下，第一個成立就回）：
     1. `route-done`、倒車、紅燈等對向列車 → null（紅燈有前窗提示）
     2. 開門中：地標還沒打招呼 → 喇叭；朋友還沒上完 → null（等）；都上車 → 車門（關）
     3. 指差題還在（`pendingPoint`；停好時月台題也還在）→ 指差鈕。指差鈕顯不顯示仍看 `pendingPoint`，nextAction 只決定亮不亮
     4. 停好（`stopped`）→ 車門（開）
     5. 任務卡還在 → 不亮（實作時依設計審改：先聽完要接誰，念完卡片自己收）
     6. **車停在軌道上**（running／in-window、速度約 0、不是紅燈）：動力 = 0 → 動力往上（賽跑提示掛著時給最高格）；動力 > 0 且 `releaseHint` → 煞車「鬆」。涵蓋關門出站、停太早、倒車退好後重新起步
     7. 進站中（progress ≥ approachAt、車在動）：
        - 慢慢看 → null（小橘自己幫忙停，`lookAssist`）
        - 小小司機、大司機（以及示範中的小站長）→ `beat === "brake"`、煞車 < 停、停車預測不在綠區 → 「停」格（小站長示範亮 B3）。已拉「輕」且預測在綠區就不亮，不教掉輕輕停
        - 小站長（沒有示範）→ 煞車 = 0 時亮整根煞車桿
     8. 沿途事件 `eventCue`：slow → 圖示桿面亮「慢」、小站長亮煞車 B2；fast → 最高格；horn → 喇叭
     9. 小鴨事件剛結束、還在同一段、煞車還拉著 → 煞車「鬆」（小站長拉 B2 讓小鴨後要放開，不然會慢到停住）
     10. 鐵橋打招呼 → 喇叭
     11. 其他 → null（巡航時什麼都不亮）
   - 已經在那一格就不亮（沿用 Cab:246 的規則）。
2. **駕駛台與前窗改用同一個標記**
   - Cab、Windshield 指差鈕只看 `nextAction`：目標控制帶 `data-next`（桿格、整根桿、喇叭、車門、指差鈕），旁邊一隻手指圖示 `NextHand`（按鈕是點一下、桿是往上推／往下拉的方向箭頭）。
   - 拿掉 `data-cue`、`data-coach`（桿）、`data-release`、喇叭 `data-hint` 的無限閃、車門 `data-ready` 光圈；車門可不可以按仍用 `aria-disabled`。示範的停車目標條外圈、淡小橘照舊（那是前窗，不是控制）。
   - 有下一步時台面加 `data-focus`：其他控制降到約七成亮度，照樣能按、有反應。
   - 減少動態：手指不動、外框靜態。
3. **補三句沒人說的**（走現有 `nextSpeech` 排程，同一站各一次）：出發「推動力，出發！」、停好「停好了，按開門」、上完車「朋友都上車了，按關門」。其他下一步本來就有語音（事件提示、示範、放煞車、地標招呼）。
4. **新手腳本改成「照亮的做」**：`novice.ts` 要碰哪個控制看 `nextAction`；動力 `notch: null` 推 `powers[1]`（慢）；nextAction 是 null 時保留原本「慢換快」的自己換格；小站長整根煞車桿等 `coachBeat === "brake"` 才拉 3（模擬會判斷的孩子）。原本第二站故意晚拉 1.6 秒那條保留給時間量測，「照亮的做全綠」另跑一組準時拉的。

測試：
- `next-action.test.ts`：每條優先序一個情境；開門後先喇叭、不亮車門；紅燈、等上車、巡航時不亮；停太早、倒車退好、關門出站（動力 0、煞車拉著）都亮動力；小站長號誌題排在推動力前、停好時月台題排在開門前；小站長進站亮整根桿、示範時亮 B3；大司機拉「輕」且預測在綠區不亮「停」；小站長小鴨後亮「鬆」。

## PR-J3 場景生動（程式繪）

1. **一個時鐘**：`WindshieldPaint.clock`（秒），View 給 `performance.now()/1000`；掛鉤 `freeze` 時固定 0，**每次畫時讀 `frozen.current`**（很多 e2e 中途 `jump({freeze:false})`）。事件動畫也改用它（順便修掉揮手、賽跑基準每次重錄都抖）。
2. **停著也會動，不加第二個 rAF**：開車中前窗本來每次 commit 就畫一次；`useGameLoop` 在停好、開門時也一直在跑（View:760、816）。在 `onFrame` 裡狀態沒變（`next === cur`）時，用 30fps 呼叫前窗的 `paint(clock)`（ref 暴露的命令式方法）。暫停、頁面隱藏時迴圈本來就停，跟著停。
3. **加的動態**（同一畫面新增會動的東西不超過兩樣，只畫幾何、不做模糊）：
   - 雲慢慢飄、會循環（三種場景）
   - 田野的樹冠輕輕搖
   - 遊樂園地標摩天輪慢慢轉
   - 天上偶爾飛過一小群鳥（田野、城市）；海邊用現成的海鷗浮在海面、帆船上下晃、浪線閃
   - **月台上等車的朋友**：進站後月台上畫要接的朋友小人（身體顏色跟座位頭像同色），揮手；停好時交給現有的 DOM 月台朋友疊層。前窗跟座位用同一組顏色，看得出「就是要接的人」
4. 減少動態：時鐘固定、不跑 rAF，畫面跟現在一樣定格。
5. 新元素都畫在號誌之前（`windshield.test` 要求號誌綠燈是最後一次 fill），不用 `createRadialGradient`（假 ctx 不支援）。

量測：production build、390×844、4 倍 CPU 節流，三種場景開車中與停著各 6 秒，平均 ≥55fps、p95 < 20ms（H4a 同方法）。測試：時鐘相關純函式（雲位置、搖擺幅度上限）、e2e「停著時前窗兩張截圖不同；減少動態時相同」、視覺基準（凍結時鐘後兩次錄位元組相同）。
