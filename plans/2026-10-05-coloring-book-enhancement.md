# 著色本增強計劃

日期：2026-10-05。狀態：提案，尚未實作。對照版本：`56f72cd4`。
檢視入口：[線上繪本著色](https://podcast-website-mu.vercel.app/games/coloring-book)。

建議把著色本做成「孩子容易動筆、作品可靠留下、故事讓孩子想再畫」的創作空間。第一版先改善保存與手機操作，第二版增加創作選擇，第三版串接故事與親子分享。

## 1. 已確認的基礎與證據範圍

線上入口於檢視時回傳 HTTP 200，封面有「打開著色本」入口。互動瀏覽器目前不可用，因此下列操作與資料結構判斷來自目前工作樹；舊視覺快照只作版面參考，不當作線上現況證明。手機手勢、線上完成面與實際保存行為仍須在實作前作一次實機基準驗證。

| 項目 | 目前已具備 | 程式證據 |
| --- | --- | --- |
| 基本流程 | 封面 → 選頁 → 畫布；換圖、完成站 | `components/coloring/ColoringBook.tsx`、`ColoringCanvas.tsx` |
| 內容 | 8 頁：4 個角色、4 個故事畫面 | `data/coloring-pages.ts` |
| 畫具 | 12 色、蠟筆、填滿、橡皮擦、3 種筆刷大小 | `lib/coloring/tools.ts`、`ColoringToolbar.tsx` |

本次執行 6 個測試檔、32 項單元測試，全數通過。範圍涵蓋畫具算法、草稿存取、流程常數、下載邊框、工具列與頁目錄；不代表實機觸控、離開時保存或完成收藏已驗證。

## 2. 需要優先改善的體驗

| 問題 | 證據與判斷 | 增強方向 |
| --- | --- | --- |
| 畫完立即換圖，最後一筆可能沒留下 | `scheduleSave` 延遲 600ms，卸載 cleanup 取消計時器；「換一張」直接回選頁，沒有等待提交 | 統一保存流程，內部離開前提交並等待交易完成 |
| 「我的作品」缺少原圖輪廓 | 儲存的是 paint 層 Blob；作品牆直接把 Blob 放進 `<img>`，沒有合成 line 層 | 草稿縮圖與完成作品使用 paint＋line 合成圖 |
| 草稿與完成作品混在一起 | 每頁只有一個當前世代 key；「我塗好了」開完成站，未另存不可變作品 | 分開「繼續塗」與「作品收藏」，同頁容許多份完成作品 |
| 手機常用動作藏在橫向工具列後方 | ≤640px 工具列不換行，3 種畫具固定在左，復原排在筆刷大小之後 | 常用畫具＋復原常駐，其餘進「更多」 |
| 某些線稿在手機上細節密集 | 實際檢視多多角色與大黃牙場景線稿，可見大量糖果、牙齒等小區塊 | 新增簡易線稿版本，保留現有版本與作品 |
| 起筆落在黑線時，防出線可能失效 | `regionMask` 起筆在黑線上回 `null`，`stampBrush` 無遮罩時只避開黑線像素，可塗到線兩側 | 先找最近可塗區；找不到時不落筆，提供短暫圖示提示 |
| 載入失敗沒有可恢復出口 | 線稿 `onerror` 只令 `ready=false`，畫面仍顯示「載入線稿中」 | 顯示重試與換圖，失敗時禁用依賴畫布的動作 |
| 內容更新會令舊作品從列表消失 | 全部頁共用 `COLORING_LINEART_REV`，列表只讀當前世代 | 每頁版本化；舊完成作品保留完整合成圖 |

以上是源碼可確認的缺口或邊界風險。手機工具是否難找、細節是否造成挫折，需要孩子與家長試用確認，不能當作已觀察到的使用者行為。

## 3. 產品原則

- 主要使用者為 3–7 歲孩子；圖示可辨識，操作配短動詞。主要觸控目標以 48px 為設計目標，至少 44px。
- 顏色由孩子決定，完成由孩子宣告。原圖是可選參考，不設定「塗對顏色」、填滿百分比或倒數時間。
- 保留現有防出線、填滿與縮放；進階自由塗色是可選模式，不削弱預設的操作保護。
- 第一版以本機保存為主，無須帳號。畫面清楚說明「作品存在這台裝置」，不暗示已雲端備份。
- 一次只提示下一個動作。常用工具看得到，收藏、列印與輸出設定放到完成流程或家長使用的出口。

## 4. 分期範圍與驗收

### A：保存可靠、手機好操作（第一個可上線版本）

| 項目 | 具體行為 | 驗收標準 |
| --- | --- | --- |
| A1 離開前保存 | 草稿保存集中管理；換圖、完成、回遊樂園走同一個提交流程。提供「儲存中／已存在這台裝置／存不下」狀態 | 收筆後 0–600ms 內換圖，回來仍有最後一筆；快速換 A/B 頁不互相污染；提交以 IndexedDB transaction complete 為準 |
| A2 載入與保存錯誤 | 線稿失敗可重試或換圖；存儲失敗仍可畫、可下載，不顯示已保存 | 模擬 404、壞 PNG、IndexedDB 不可用、交易 abort、配額失敗；畫面有明確出口，不永久停在載入中 |
| A3 手機工具列重排 | 蠟筆、填滿、擦掉、復原常駐；筆刷大小用單一入口；清空、原圖參考、下載進更多工具。色盤保留快速換色 | 320/390/430px 寬不用橫向捲工具列即可使用 4 個常用動作；開更多工具不誤畫；鍵盤與讀屏可進出 |
| A4 作品縮圖正確 | 「繼續塗」縮圖顯示線稿與顏色；保存最近編輯時間、縮圖及必要 metadata | 未塗區保持白底、黑線完整；與畫布及下載內容一致；回選頁立即看得到最新筆觸 |

內部導覽可以等待保存；瀏覽器強制關閉與作業系統終止不能依賴最後一個非同步事件。以收筆提交、背景事件補存及復原機制降低遺失風險，實機驗收需分別測試內部換頁、正常重整、切背景與強制終止，不承諾任意時刻零遺失。

### B：孩子更容易畫，也有更多創作選擇

| 項目 | 具體行為 | 驗收標準 |
| --- | --- | --- |
| B1 大色塊線稿 | 先為多多與小紅各加一份簡易版，主角完整、減少密集背景細節；原版繼續可用 | 原版草稿仍能續畫；簡易版有獨立 id/版本；代表性區塊閉合，填色不漏進相鄰區；手機看得出表情與輪胎 |
| B2 更容錯的落筆 | 黑線附近起筆先決定一個可塗區，再沿用整筆遮罩；區域算法支援快取 | 起筆黑線上、交叉點、窄區塊、邊緣各有像素測試；拖過相鄰區不染色；雙指手勢不留下墨點 |
| B3 重做與清空復原 | 復原後可重做；新筆觸清除重做分支；清空仍可復原；依像素記憶體上限管理歷史 | 畫→填→擦→復原→重做順序正確；連按不錯位；清空→復原內容一致；沒有無限增長的歷史 |
| B4 自由創作模式 | 預設「安心塗」保留不出線；更多工具可切「自由塗」，容許跨區畫彩虹、花紋；提供簡單色組 | 模式切換保留作品；黑線仍清楚；選模式不新增整頁設定關卡；色組不改掉孩子已選的顏色 |
| B5 首次引導與完成狀態 | 新手仍先塗一筆再提示填滿；成功使用後收起提示。引導狀態與真正非空作品狀態分開 | 回訪不重複整套教學；復原／擦光／清空後空白狀態正確；有內容時孩子可自行按「我塗好了」 |

第一批簡易版是內容試點，通過孩子試用後再擴到 8 頁，避免一次改全部線稿。線稿品質包含角色一致性、輪廓閉合與手機可操作性；增加圖片數量之前，先確保兩份試點有這三項品質。

### C：作品收藏、故事活動與親子回訪

| 項目 | 具體行為 | 驗收標準 |
| --- | --- | --- |
| C1 完成作品收藏 | 完成時另存一份完整合成圖；完成站主動顯示收藏結果。主動作仍是換圖，另有下載／再塗 | 同頁可保存多份作品且不覆蓋；完成收藏失敗時不冒出成功文案；「再塗」明確區分繼續原稿與開新稿 |
| C2 首頁繼續作品 | 有草稿的回訪者可從封面「繼續塗」進最近一頁；選頁卡顯示已有草稿 | 無草稿仍是原本單一開書入口；失效頁 id 有回選圖出口；不自動覆蓋歷史作品 |
| C3 故事著色活動 | 先做 2 個主題：小紅的彩虹賽車、多多的牙齒與糖果。活動是一句邀請，不判對錯；完成後可看對應故事 | 與頁面故事 id 明確關聯；指定頁面的直接連結可用；返回保留草稿；不強制先聽完故事才能畫 |
| C4 分享與列印 | 完成面提供存圖片；支援檔案分享的裝置可開原生分享，其他裝置用下載。家長可列印未上色或已完成的 A4 圖 | iOS Safari、Android Chrome 各驗證分享與降級；列印不截角色；只在點分享時開系統分享，不自動上傳 |

第一版故事串接用完成後的故事連結。若試用確定需要「邊聽邊塗」，再整合現有播放器生命週期、音效靜音與背景播放；不另造一套 audio 播放器。

## 5. 建議資料與程式拆分

保存與作品模型是 A/C 共用基礎，先設計再做 UI，避免第一版存完又需要整庫重寫。

| 資料 | 最小欄位 | 用途 |
| --- | --- | --- |
| 頁面 | `id`、`lineArtRevision`、`variant`、可選 `storySlug` / 活動提示 | 每頁版本、簡易版及故事關聯 |
| 草稿 | `draftId`、`pageId`、版本、`paintBlob`、`thumbnailBlob`、`updatedAt` | 續畫、最近作品、完整縮圖 |
| 完成作品 | `artworkId`、來源頁與版本、`compositeBlob`、`thumbnailBlob`、`createdAt` | 同頁多作品、舊版本收藏、下載 |
| 偏好 | 最近畫具／顏色、首次引導狀態 | 降低回訪操作成本 |

實作落點：

- `lib/coloring/draft-storage.ts`：升級 IndexedDB schema、交易完成語意、錯誤分類；把舊 Blob 草稿轉成新記錄，保留舊 store 至遷移驗證完成。
- 新增 `lib/coloring/artwork-storage.ts`：完成作品 CRUD 與縮圖分頁。舊世代草稿無法對齊新線稿時，保留舊線稿資源或合成結果供查看；不要直接拿新線稿去覆蓋。
- 從 `ColoringCanvas.tsx` 抽出 `useColoringPersistence`、`useColoringHistory`、`useColoringGesture`，保留現有畫布像素算法的責任邊界。保存工作使用頁 id、版本與寫入序號，防止舊回呼覆蓋新內容。
- `ColoringToolbar.tsx` 與 CSS：常駐工具與更多工具面板；面板焦點還原、Esc、畫布事件遮蔽。
- `ColoringPagePicker.tsx`：繼續塗／完成收藏分區、最近排序、縮圖延遲載入，避免 `getAll()` 一次取所有高解析度 Blob。
- `ColoringBook.tsx`：最近作品入口、指定頁面連結、導覽前保存協調。
- `data/coloring-pages.ts` 與測試：新增內容 metadata，將「固定 8 頁」改成基本內容覆蓋與資料一致性守衛。

第一批先量測填色與筆觸延遲，再決定是否要 Web Worker／預計算區域。源碼已使用 dirty rect、rAF 合成及合併指標事件，不能把這些既有優化列為新功能。

## 7. 驗證與試用

現有基準命令，本次 32 項已通過：

```sh
npx vitest run lib/coloring/tools.test.ts lib/coloring/draft-storage.test.ts lib/coloring/flow.test.ts lib/coloring/export-frame.test.ts components/coloring/ColoringToolbar.test.tsx data/coloring-pages.test.ts
```

後續按里程碑補驗：

- 像素：黑線起筆、區域邊緣、填色閉合、縮放後落筆、復原重做、縮圖合成內容。
- 保存：延遲視窗內換頁、交易 abort、連續換頁、清空後舊回呼、quota、舊版本遷移、同頁多份完成作品。
- 操作：`e2e/coloring.spec.ts` 新增離開續畫、工具常駐、載入重試、收藏與重做；保留現有 multiply 合成與填色防漏回歸。
- 視覺：320×568、390×664、390×844、430×932、768×1024、1280×720、手機橫向；日夜模式及減少動畫。
- 實機：至少一台 iPhone Safari 與一台 Android Chrome，確認雙指取消誤觸、背景切換、分享、列印；桌機 Chromium 的觸控模擬不能替代。
- 可及性：工具具名稱與選中狀態；色盤以合適的鍵盤群組模型操作；更多面板焦點可返回，錯誤訊息可讀屏；可選擇後續提供區域點選著色入口。

性能是待量測目標：代表性 1024px 線稿上，填色可見回饋 p95 ≤150ms，連續筆觸盡量不出現 >100ms 主執行緒停頓；以 M0 選定的實機為準。每個新版本記錄執行時間與歷史像素記憶體，不把測試機數據當所有手機保證。

小規模試用建議邀 5–8 組親子，涵蓋 3–4 歲與 5–7 歲。觀察能否自行選色並開始塗、找得到復原、回來找得到作品，以及願不願意再畫另一份。以「不靠家長提示完成基本流程」與「作品沒有遺失」判斷第一版是否成功；不使用填滿比例評價孩子的創作。

後續可選：數種紙張／蠟筆質感、貼紙、下載內容包與離線著色。離線包需另外快取路由、JS、線稿與必要圖片；目前 IndexedDB 草稿保存不等於可離線開啟著色本。先完成 M1–M3，再依試用需求排序。
