## 1. 手捲凸出點餐泡泡

### 現況
- 點餐泡泡每一格是固定大小（34–60px）的方格，但手捲圖（511×986）是瘦長的。390 寬實測：格子 39px，手捲圖 76px 高，從泡泡底部凸出去，還蓋住下面那排進度小盤。
- 原因：`BaseArt` 在元素上寫了 `width: 100%; height: 100%`，蓋過 `.bubbleItem > img { width: 88%; height: 88% }`（`components/games/DinoSushiKitchen.module.css`）。格子是 `display: grid` 搭配自動列高，`height: 100%` 被當成 auto，圖就照原比例長高。
- 握壽司、軍艦接近橫的或方的，所以看不出問題；料的圖不會出現在泡泡裡的飯格。

### 做法
- 只改 CSS：讓 `.bubbleItem` 的格線固定在格子大小（例如 `grid-template: minmax(0, 1fr) / minmax(0, 1fr)`），`height: 100%` 才會算成格子高度，`object-fit: contain` 就會把手捲縮進格子裡。
- 順便讓圖跟原設計一樣留約 6% 的邊（88%），三種飯在泡泡裡看起來一樣大。
- 不改 `BaseArt` 的元件介面（選飯鈕、備料盤也用它）。

### 驗收
- 三種飯（握壽司、軍艦、手捲）在 320×568、390×844、667×375、844×390、1280×800 下，泡泡裡每張圖的框都在它的格子裡（誤差 1px），也不蓋到進度小盤。
- 新增 e2e：逐格比對圖與格子的框，至少涵蓋手捲單。
- 選飯鈕、備料盤上的飯看起來跟現在一樣（截圖比對）。

## 2. 招牌字被多多擋住

### 現況
- 直式木招牌（`shop/sign.webp`）掛在多多左上方，「多多壽司」四個字用程式疊在牌面上。#214 換成黏土貼紙後多多變大，字剛好落在多多頭後面：390、667、1024、1280 寬都完全看不到，844×390 只露出一個「多」。
- 矮舞台（高度 ≤190px，例如 320×568）本來就把招牌和燈籠收起來。
- 牙刷出現時，招牌和燈籠會讓位（`[data-brush="true"]`）。

### 做法（待決定，建議 A）
- **A. 店名改寫在櫃台前板上（建議）**：櫃台前板（`shop/counter.webp`）是一整條橫貫舞台底部的木板，多多站在它上面，什麼都擋不到。「多多壽司」用程式文字刻在前板左半部（木刻深色、橫書），右半部留給疊盤；拿掉直式招牌。
  - 好處：不用新素材、各尺寸都看得到、左上角空出來給牙刷。
  - 要注意：前板在 390 寬約 23px 高，字約 14px；送餐盤滑過去時會短暫蓋到前板中段，所以字要放在左邊、避開送餐盤的路徑。矮舞台前板只剩約 13px，照現在的做法不顯示店名。
- **B. 生一張橫式招牌掛在雨棚下、多多頭上方**：要用付費生圖（受成本紅線約束，見第 3 項），而且頭上方空間在 390 寬只有約 40px，容易跟牙刷、燈籠擠在一起。不建議。
- **C. 招牌移到多多右邊**：右邊有點餐泡泡和圓窗，沒有位置。不可行。

### 驗收（以 A 為準）
- 320×568 以外的 6 種尺寸（360×640、390×844、667×375、844×390、932×430、1280×800），在選飯、加料、吃、反應、疊到 4 盤時，「多多壽司」四個字的中心點都點得到文字本身（`elementFromPoint`），沒被疊盤、送餐盤或多多蓋住。
- 字在日夜兩種主題下對比 ≥4.5:1（卡面日夜不反轉，實際上只要算一次）。
- 拿掉直式招牌後，原本給它讓位的規則（`.lanternRight` 的位置算式、牙刷讓位清單）一起清掉，不留沒用到的 CSS。
- 設計審要看 390 與 1280 的前後截圖。

## 3. 金盤素材

### 現況
- 一次做對的盤子是「金盤」，在疊盤、結算頁那排盤子和結算提示裡出現。
- 目前沒有金盤素材，是把薄荷綠盤子（`shop/plate.webp`）套 CSS 濾鏡（`sepia(0.8) saturate(2.8) hue-rotate(8deg) brightness(1.05)`，`lib/games/dino-sushi/art.tsx` 的 `PLATE_FILTER.gold`）。結果看起來是一片亮黃色的平面圓片，沒有其他黏土素材的柔和陰影，也不像規格寫的「金邊盤」。

### 做法（待決定）
- **素材規格**：
  - 檔名 `public/games/v2/dino-sushi/shop/plate-gold.webp`，695×403、透明底。
  - 角度、光源、厚度跟 `plate.webp` 完全一樣，疊在同一疊裡要對得齊。
  - 盤面是奶油白或淺暖色釉，厚的金色盤緣；霧面黏土質感，可以有一兩個小亮點，但不要鏡面金屬。
  - 縮到 48px 寬時，跟藍盤分得出來：亮度差要夠，而且盤緣形狀明顯，不能只靠色相。
- **圖從哪來**（三選一）：
  1. **你提供**：跟其他黏土素材一樣由你核准原檔（建議，跟 #214 的素材來源一致）。
  2. **用生圖腳本產一張**：照 `scripts/generate-dino-sushi-cover.ts` 的模式寫一支只產這張的腳本。依成本紅線，**動手前要在聊天裡列出「1 張、1 次呼叫」並等你文字確認**；產出先放暫存、看過才上線，不自動重抽。
  3. **先不做素材**：改成藍盤加一圈 CSS 金邊（橢圓描邊＋漸層）。免費，但跟黏土質感不完全一致，只當過渡用。
- **程式**：`PlateArt` 的 `gold` 改用新圖，拿掉 `PLATE_FILTER.gold`。迴轉帶上的粉、薄荷、紫裝飾盤照舊用濾鏡（它們刻意退在背景）。

### 驗收
- 疊盤、結算那排盤子、結算提示的金盤都換成新圖；跟藍盤混疊時邊緣對齊（截圖比對 4 盤一金三藍、4 盤全金）。
- 在灰階截圖下，金盤和藍盤仍分得出來。
- 設計審看結算頁 390 與 1280 截圖。

## 4. 圖檔縮小

### 現況（2026-10-14 實測，正式 build）
- 一進標題頁就預先下載 39 個檔、共 **3.7MB**（`useDinoSushiClayPreload`、`useDuoDuoStickerPreload`），手機用行動網路時偏重。
- 廚房裡同時解碼的圖約 **80MB**（32 張 × 寬 × 高 × 4）。多多的 9 張 1024×1024 貼紙疊在一起切換，光這些就約 36MB。舊 iPad 或低階 Android 可能會卡，甚至讓分頁被系統回收。
- 實際最大顯示寬度（CSS px）遠小於原圖：

| 圖 | 原圖寬 | 手機最大顯示 | 桌面最大顯示 |
|----|--------|--------------|--------------|
| 多多貼紙 ×9 | 1024 | 201 | 345 |
| 托盤料 ×12 | 580–1024 | 84 | 138 |
| 飯 ×3、手捲前片 | 511–745 | 84（選飯鈕） | 備料盤上約 240 |
| 備料盤 | 761 | 198 | 280 |
| 雨棚／櫃台／牆 | 1024–1407 | 約 346–394 | 約 393–447 |
| 圓蓋、燈籠、盤子、圓窗、招牌 | 404–821 | 31–87 | 35–94 |

### 做法
- 新增 `scripts/optimize-dino-sushi-assets.ts`（`sharp` 已經是依賴；寫法參考 `scripts/optimize-roamer-assets.ts`）：
  - 從原檔產生縮小副本到同目錄的 `sm/` 子目錄，例如 `food/sm/salmon.webp`。**原檔不動**（素材是主人核准的原檔）。
  - 每張的目標寬度＝「所有畫面狀態裡的最大顯示寬度 × 2」，取 64 的倍數，最小 128。實作時先寫一支量測腳本（類似這次用的 Playwright 量測），把每張圖在 7 種尺寸、選飯／加料（三料、三種飯）／吃／結算各狀態下的最大顯示寬度輸出成表，再寫進腳本的設定。
  - 提供 `--verify` 檢查：每個原檔都有副本、尺寸正確、副本比原檔小。
  - 產出的副本 commit 進 repo（跟其他優化腳本一樣），不在 build 時才產生。
- 程式改用副本：`lib/games/dino-sushi/art.tsx`、`duoduo-sticker.tsx`、`DinoSushiShop.tsx` 改指向 `sm/` 路徑，用同一個小函式統一換路徑，不要每處各寫一次。
- 預載保持現在的做法（避免換表情時閃一下），只是載的變成小圖。
- 封面 `cover.webp` 走 `next/image`，不在範圍內。
- 不用 `srcset`：單一副本已經夠 2 倍螢幕使用，`srcset` 對絕對定位的疊層和 CSS 背景圖（托盤）比較麻煩。

### 驗收
- 標題頁預先下載的總量 ≤ 1.5MB（目前 3.7MB）。
- 廚房裡同時解碼的估算 ≤ 35MB（目前約 80MB）。
- 390×844@3x 與 1280×800@2x 的截圖跟改之前比，人工目檢看不出變糊；特別看多多的臉、備料盤上的三料壽司、雨棚。
- `npm run optimize:dino-sushi-assets -- --verify` 綠；`verify:no-public-fs` 等既有檢查不受影響。

## 5. 「念出來」開關

### 現況
- 壽司屋（#217）和消消樂（#220）都會朗讀，現在共用 `lib/games/shared/speech.ts`，兩款都只跟抬頭的「音效」開關和遊戲音量。
- 想要「留音效、只關人聲」的家長目前沒有選項。#217 拿掉了壽司屋舞台上的獨立朗讀開關，因為它蓋住牙刷，而且畫面上有三顆一樣的喇叭。

### 做法
- **範圍（待決定，建議兩款共用一個）**：在「遊戲設定」對話框（`components/games/GameChrome.tsx` 的 `SettingsDialog`）加一列「念出來」開關，放在「遊戲音量」下面。說明文字：「訂單、提示和多多的話用聲音念出來」。兩款遊戲都適用；方塊轉轉沒有朗讀，不顯示這一列。
- **存檔**：`GameKitPreferenceStore` 加 `voiceEnabled: boolean`，預設 `true`。在 `normalizeGameKitPreferences` 補預設值，舊存檔讀進來就是開著。`lib/gamekit/progress/settings.ts` 的 `GameKitSettings`、`useGameKitSettings` 一起加 setter。這是加欄位，不改舊欄位，也不需要搬資料。
- **接線**：朗讀要不要念＝`soundOn && gameVolume > 0 && voiceEnabled`。`useDinoSushiSpeech`、`useCandyMatchSpeech` 多收一個參數；兩個 View 從 `useGameKitSettings` 讀。
- **畫面**：`voiceEnabled` 關掉時：
  - 壽司屋泡泡上的小喇叭徽章、點泡泡重聽都收起來（跟關音效一樣）。
  - 消消樂的「再聽一次」收起來。
  - 正在念的句子立刻停。

### 驗收
- 單元測試：
  - 舊存檔（沒有這個欄位）讀出來是 `true`。
  - 關掉後兩款都不念、不顯示重聽，正在念的會停。
  - 打開音效、但關掉朗讀時，合成音效照常有聲。
- e2e：在設定裡關掉「念出來」，用假的 `speechSynthesis` 確認不念，並保留「開著時有念」的正向對照（照 #217 的寫法）。
- 設定對話框在 320 寬放得下，開關 ≥44px（設定是家長介面，比照抬頭 44px）。

## 6. 難度分級

### 現況
- 一輪 5 單，料數固定 `[1, 1, 2, 2, 3]`（`lib/games/dino-sushi/orders.ts` 的 `ORDER_SIZES`）。
- 2026-10-14 的難度審：年齡合適、略偏簡單。#219 讓提示從新訂單出現後 4.5 秒才亮，會比原本難一些，先觀察。
- 星星只有一關（`DINO_SUSHI_LEVEL_INDEX = 0`），整款最多 3 星；存檔裡的 medal bit 是相容性契約（`lib/games/dino-sushi/medals.ts`）。

### 做法（待決定，建議 A）
- **A. 自動調整，不加選單（建議）**：
  - 新增三檔料數：輕鬆 `[1, 1, 1, 2, 2]`、一般 `[1, 1, 2, 2, 3]`（現在）、進階 `[2, 2, 3, 3, 3]`。
  - **起始檔**：沿用既有存檔判斷，不新增存檔欄位。已經拿過 3 星就從「進階」開始，否則從「一般」開始。
  - **同一次遊玩內**：一輪 5 單都一次做對就升一檔，一次做對 ≤2 單就降一檔；只記在記憶體裡，重新整理或離開就回到起始檔。
  - 進階時閒置提示改成 7 秒（`IDLE_HINT_MS` 依檔位決定）。首單的教學手指只在「一般」以下出現。
  - 星星條件不變（還是看一次做對幾單），所以進階比較難拿星，但已經拿到的星不會掉。
  - 標題頁不顯示檔位，孩子不用選；可以考慮在多多的開場台詞輕描淡寫地提一句（例如「今天好餓，想多吃一點！」）。
- **B. 標題頁兩顆鈕「小廚師／大廚」**：孩子或家長自己選。大廚要另算一組星，就得動星星系統：新增 level 1、改「整款最多 3 星」的說明與測試、家長儀表板的總星數，跨模組，接近 L3。不建議現在做。
- **不做的難度手段**：泡泡收起來要靠記憶、規定放料順序、計時。這些對 4–6 歲的主要玩家太硬，也違反「沒有倒數、做錯也能補」的設計原則。

### 驗收（以 A 為準）
- `buildOrders` 收一個檔位參數；三檔各自的訂單仍然是決定性的（同一個 seed 產生同一組，視覺測試用的 `__dinoSushiSeed` 繼續有效），相鄰兩單不一樣，只點托盤上的家常料。
- 單元測試：
  - 升降規則（5/5 升、≤2 降、其他不變、到頂或到底不再動）。
  - 已有 3 星時從進階開始。
  - 檔位不影響 medal bit。
- e2e：既有壽司屋測試全過（預設檔位要讓既有測試的訂單維持原樣，或者測試明確指定檔位）。
- 設計審：進階的第 5 單（飯＋三料）在 320 寬泡泡放得下（#217 已經處理三料寬度，這次要確認連續三單都是三料時的節奏）。
- 上線後在 TODOS 記錄觀察方式：家長儀表板看重玩次數與星星分布，兩週後回顧數字。
